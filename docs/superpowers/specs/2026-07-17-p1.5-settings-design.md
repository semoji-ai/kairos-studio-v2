# Kairos Studio v2 — P1.5: 설정 창 설계

날짜: 2026-07-17
상태: 승인됨 (사용자 확인)

## 목적

채팅 앱에 설정 화면을 추가한다. 범위 4가지(사용자 선택):
1. CLI 상태 패널 — claude/codex 설치·버전·로그인 상태 + 미인증 시 로그인 안내
2. 데이터 저장소 설정 — 학습데이터(SQLite) 위치 표시·변경(NAS 가능) + 용량 표시
3. 라우팅 규칙 편집 — 기본 provider, 규칙 on/off
4. 권한 모드 설정 — codex sandbox / claude permission-mode (보수적 옵션만)

전제: CLI 인증은 CLI 자체 로그인(`claude /login`, `codex login`)이다. 앱은
대신 로그인하지 않는다 — 상태 감지와 안내만 한다.

## settings.json

위치 고정: 사이드카의 `KAIROS_CONFIG_DIR` env(Tauri가 app-data dir 전달) 아래
`settings.json`. env 미설정 시 `~/.kairos-studio/`. 설정 파일 위치 자체는 설정
대상이 아니다(닭-달걀 방지).

```json
{
  "data_dir": "~/.kairos-studio",
  "default_provider": "claude",
  "routing_rules_enabled": true,
  "codex_sandbox": "read-only",
  "claude_permission_mode": "default"
}
```

- 모든 키 optional — 없으면 위 기본값. 알 수 없는 키는 보존(전방 호환).
- 검증 화이트리스트: default_provider ∈ {claude, codex},
  codex_sandbox ∈ {read-only, workspace-write},
  claude_permission_mode ∈ {default, acceptEdits}. 그 외 값은 400.
- `bypassPermissions` / `danger-full-access` 류는 UI·검증 어디에도 없음(안전).

## 사이드카 변경 (core/)

### settings.py (신규)
- `load() -> dict` — 파일 없으면 기본값. 병합(파일값이 기본값 위에).
- `save(patch: dict) -> dict` — 화이트리스트 검증 후 병합 저장, 결과 반환.
  검증 실패는 ValueError.

### 라우트 (server.py)
- `GET /settings` (authed) → 현재 설정
- `PUT /settings` (authed) → patch 병합 저장. data_dir 변경 시:
  - 새 경로 생성 가능해야 함(mkdir -p). 실패 시 400, 설정 저장 안 함.
  - 대상에 kairos.db가 없고 기존 DB가 있으면 **복사**(원본 유지 — 이관이 아닌 복사,
    P1.5에서는 자동 삭제 안 함).
  - Store를 새 경로로 재오픈(재시작 불요).
- `GET /cli/status` (authed) → provider별
  `{installed: bool, version: str|null, authed: bool|null, login_hint: str}`
  - installed: shutil.which
  - version: `<cli> --version` (짧은 타임아웃, 실패 시 null)
  - authed: codex는 `codex login status` exit code. claude는 실측으로 판별
    방법 확인 후 구현(공식 서브커맨드 없으면 null 반환하고 UI는 "확인 불가" 표시
    — 억지 추정 금지).
  - login_hint: 미인증 시 사용자가 터미널에서 칠 명령 문자열.
- `GET /storage` (authed) → `{data_dir, db_bytes}` (kairos.db 파일 크기)

### 설정의 적용 지점
- router: `routing_rules_enabled=false`면 멘션(@claude/@codex)만 존중하고
  나머지는 전부 default_provider. 멘션은 항상 이긴다.
- providers/claude: `--permission-mode <설정값>`
- providers/codex: `--sandbox <설정값>`
- Store: data_dir 변경 시 재오픈. NAS 미마운트 등으로 열기 실패하면
  **로컬 기본 경로로 폴백**하고 `/storage` 응답에 `fallback: true` 포함,
  UI가 경고 표시.

## UI 변경 (app/)

- 헤더(사이드바 상단) ⚙️ 버튼 → 설정 화면 토글(채팅 ↔ 설정, 라우팅 라이브러리
  없이 상태로 전환).
- `Settings.tsx` 섹션 3개:
  1. **CLI 상태**: provider별 카드 — 설치/버전/로그인 뱃지(✅/❌/확인불가),
     미인증 시 login_hint 표시 + "복사" 버튼
  2. **저장소**: 현재 data_dir, DB 용량(MB), 경로 입력 + 저장. fallback 경고 표시.
  3. **라우팅·권한**: 기본 provider(라디오), 규칙 토글, codex sandbox /
     claude permission 드롭다운(화이트리스트 값만)
- api.ts에 getSettings/putSettings/cliStatus/storageInfo 추가.

## 테스트

- settings.py: 기본값/병합/화이트리스트 검증/알 수 없는 키 보존 (pytest)
- server: GET/PUT /settings 왕복, 잘못된 값 400, data_dir 변경 시 DB 복사+재오픈,
  실패 시 400 및 기존 설정 유지, /cli/status는 fake CLI로 (KAIROS_*_CMD 재사용),
  /storage 크기 응답
- router: rules_enabled=false + default_provider=codex golden 케이스 추가
- providers: 설정값이 커맨드라인에 반영되는지 (fake CLI가 받은 argv 검증)
- UI: tsc + build

## 완료 기준

1. 설정 화면에서 claude/codex 설치·로그인 상태가 보인다
2. data_dir을 바꾸면(존재하는 경로) DB가 복사되고 새 대화가 새 위치에 쌓인다
3. 기본 provider를 codex로 바꾸고 규칙을 끄면 일반 질문이 codex로 간다
4. 권한 모드 변경이 실제 CLI 호출 인자에 반영된다
5. 잘못된 값(경로 생성 불가, 화이트리스트 외 값)은 400이고 기존 설정이 유지된다

## 제외 (YAGNI)

- 설정 파일 위치 변경, 라우팅 정규식 커스텀 편집기, 자동 DB 이관(복사만),
  CLI 자동 로그인, 위험 권한 모드 노출
